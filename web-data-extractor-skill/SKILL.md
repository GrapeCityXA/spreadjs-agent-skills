# WebDataExtractor（网页数据 → 在线编辑）

**把网页数据送进一个带完整工具栏的 SpreadJS 设计器**在线编辑页，让用户像用 Excel 一样查看、编辑、增删行列，再回传给 Agent 继续处理。数据来源三选一：内置自动提取（表格/列表/定义列表/重复卡片）、`--data` 直接接收 Agent 自行取到的二维数组、`--cdp` 连接用户已登录的浏览器读取**渲染后**的页面（登录 / JS 渲染 / SPA 也能拿到）。

## 为什么优先用本技能（核心价值）

**本技能的核心交付是「网页数据 → 浏览器端 SpreadJS 在线编辑」，而不是某个特定的 HTML 结构。** 带完整 Ribbon 工具栏、Excel 式交互的在线设计器，是 Agent 自身能力难以复现的——Agent 自己的「输出」只能给文本或 JSON，给不了可交互的电子表格。

因此，只要用户想「把网页数据整理成可编辑表格并在线调整」，就应优先使用本技能，**不要因为页面没有规整的 `<table>`/列表/卡片而跳过它**：

- 页面结构不规整 → 用 `--selector` / `--type` 精确指向目标区域，或让 auto 尽力匹配；
- 页面**需登录或 JS 动态渲染**、直接抓取不到 → 优先用 `--cdp` 连接用户**已登录**的浏览器读取渲染后的页面（登录态、JS、SPA 一次解决），比 Agent 自己模拟取数更可靠；
- 页面是 JS 渲染、且不方便走 CDP（如 Agent 跑在远端够不到用户浏览器）→ Agent 先用**自己的能力**取数（模拟渲染、读接口返回等），把二维数组写入 JSON 文件，再用 `--data` 交给本技能进入 SpreadJS 编辑；
- 提取到的数据不完整 → 没关系，用户在编辑页里补齐或调整即可。

一句话：**抓取是手段，SpreadJS 在线编辑与回传才是本技能的不可替代价值。**

## 使用场景（触发条件）

**使用此技能，当：**
- 用户要求“抓取/提取这个网页上的表格/列表/数据”，并提供了网页 URL；
- 用户想把网页数据做成可编辑表格，或“把网页里的表/列表整理一下”；
- 用户给了 URL，**无论页面是否有规整表格/列表**——结构复杂时用 `--selector`/`--type`，或 Agent 自己取数后用 `--data`；
- 用户想「在线编辑/调整网页数据」，或把网页数据交给人用 Excel 式界面确认后再继续；
- Agent 已自行取得网页数据（如 JS 渲染页、接口返回），想把它送入 SpreadJS 让用户编辑——用 `--data`；
- 目标页面**需登录 / JS 渲染 / SPA**，直接抓取拿不到数据——用 `--cdp` 连接用户已登录的浏览器读取（需用户配合启动调试浏览器，见下文）。

**不要使用，当：**
- 用户没有提供 URL，也没有数据文件，只是泛泛询问；
- 数据来自本地文件/附件（改用 `online-xlsx-editor`）；
- 页面需登录且用户无法/不愿提供调试浏览器（此时若 Agent 能另途取数，仍可用 `--data`）。

## 支持的提取类型（--type）

| 类型 | 提取内容 |
| --- | --- |
| `table` | `<table>` 表格（智能选最大表 / 自定义选择器） |
| `list` | `<ul>/<ol>` 列表，每个 `<li>` 一行；li 内部结构稳定时按字段拆多列 |
| `dl` | `<dl>` 定义列表，`<dt>/<dd>` 键值对 → 两列 |
| `blocks` | 重复的兄弟 DOM 结构（卡片/新闻项/产品项），每块一行、按字段对齐拆列 |
| `auto` | 默认。按 table → dl → list → blocks 顺序自动检测 |

> **数据来源二：`--data <file.json>`** —— 不抓网页，直接读取 Agent 自行整理的二维数组
> （JSON，首行为表头，如 `[["列1","列2"],["a","1"]]`）进入编辑器，`kind` 为 `data`。
> 适合页面结构特殊、JS 动态渲染等内置提取搞不定的情况。

> **数据来源三：`--cdp`** —— 连接用户本机**已登录**的浏览器读取目标页面**渲染后**的 DOM
> （登录态 / JS 渲染 / SPA 都能拿到），再走同样的提取管线（结果 `kind` 同 URL 入口）。
> 需要用户先用调试端口启动自己的 Chrome 并登录目标站点，见下方「前置要求」与工作流。

## 前置要求

- 运行环境 Node.js ≥ 18；零第三方依赖（纯 Node 内置模块），**无需 npm install**。
- `--cdp` 模式额外需要 **Node ≥ 22**（内置全局 WebSocket）且必须运行在**用户本机**。
- 用户浏览器需能访问 jsdelivr CDN（编辑页从 CDN 加载 SpreadJS 19.1.1）。

### --cdp 的浏览器准备（需向用户说明，让用户配合）

1. 关闭当前 Chrome，用调试端口 + **独立 profile** 启动（避免和默认浏览器冲突）：
   ```
   chrome.exe --remote-debugging-port=9222 --user-data-dir="%TEMP%\skill-cdp" --remote-allow-origins=*
   ```
2. 在这个浏览器里**登录目标网站**（登录态保存在该 profile 里）。
3. 技能连接 `127.0.0.1:9222`（端口不同用 `--cdp-port <端口>` 指定），打开新标签页读取页面后自动关闭。
   - 连接失败时技能会在 stderr 打印同样的启动引导。

## 工作流（Agent 执行步骤）

1. **判断数据入口**：
   - 有网页 URL 且页面是静态 HTML → 用 URL 入口；
   - 页面**需登录 / JS 渲染 / SPA**、直接抓取拿不到，且用户能配合启动调试浏览器 → 用 `--cdp` 入口（先向用户说明启动步骤并让其登录）；
   - 页面结构特殊、或不便走 CDP、或 Agent 已自行取到数据 → 把二维数组写入临时 JSON 文件，用 `--data` 入口。
2. **运行技能**（在技能目录执行，建议加 `--no-open` 避免无图形界面弹浏览器）：
   ```
   node index.js <URL> [--type table|list|dl|blocks|auto] [--selector <CSS选择器>] [--no-open] [--chart-config <文件.json>]
   node index.js <URL> --cdp [--cdp-port <端口>] [--no-open]     # 用用户浏览器读取登录/JS渲染页
   node index.js --data ./网页数据.json [--no-open]
   ```
   编辑页默认自动套用样式（表头/边框/隔行/行高列宽自适应/冻结表头）并据数据生成图表
   （独立「图表」工作表）；`--no-style` / `--no-chart` 可分别关闭。
   网页抓取的数据基本都是字符串，凡**能干净转成数字**的字符串（含千分位/金额符号/百分号/「万」）
   会自动转成 number 再写入单元格，保证图表正常渲染；日期/时间/带分隔符或前导零的编号不会被误转。

   **AI 自行选择图表（可选，推荐列多时用）**：技能会在 stdout 打印「列名: …」，Agent 据此判断
   哪几列适合做图，写一个 JSON 后用 `--chart-config` 重跑（列可用**表头名**或**列号**）：
   ```json
   { "type": "line", "category": "产品名称", "series": ["销量", "利润"] }
   ```
   - `type`：`column` / `bar` / `line` / `pie`（默认 `column`）；饼图只取第一个 `series` 列。
   - `category`：类别列；省略时自动取第一个非数值列。
   - `series`：数值列，至少 1 个；只画这里指定的列，其余列（即使含数值）不画。
   - 不传 `--chart-config` 时按启发式自动选列（所有数值列，**上限 6 个**系列）。
3. **展示链接**：把 stdout 中打印的 `http://localhost:<端口>/index.html` 链接展示给用户，并提示：
   “请在浏览器打开，用顶部工具栏编辑表格，完成后点击右上角『下载表格 (xlsx)』。”
   注意提示用户：编辑页已自动套用样式与图表（如需原样数据可加 `--no-style`/`--no-chart` 重新生成）。
4. **等待完成**：进程持续运行，直到用户在浏览器点击「下载表格」后自动退出。点击会**直接下载 xlsx 文件**，
   同时仍通过 `POST /save` 把编辑结果（二维数组 + xlsx base64）回传给 Agent——两条路径都会执行，
   用户手里一定有文件，Agent 也能拿到结构化数据。
5. **解析结果**：取 stdout 中**最后一个 JSON 对象**作为结果。
6. **继续原任务**：用结果中的 `table`（二维数组，首行为表头）或 `xlsxPath` 继续执行用户原始指令。

## 输出协议（Agent 解析）

```json
{
  "type": "list",
  "kind": "list",
  "table": [["a", "span"], ["手机", "¥4999"]],
  "jsonPath": "<技能运行目录>/temp_skill_web/data.json",
  "xlsxPath": "<技能运行目录>/temp_skill_web/edited.xlsx",
  "summary": { "rowCount": 4, "colCount": 2 },
  "extractionHint": "从 3 个列表项中提取了 3 行 × 2 列",
  "savedDir": "<技能运行目录>/temp_skill_web"
}
```

- `type` / `kind`：数据来源（`table`/`list`/`dl`/`blocks`；用 `--data` 时为 `data`；`--cdp` 是读取方式，`kind` 同 URL 入口）。
- `table`：用户编辑后的二维数组（首行为表头），推荐用于后续分析/汇总。
- `extractionHint`：提取阶段提示（如数据来源与行列数）。

## 权限与安全

- 启动本地 HTTP 服务、写临时文件、打开浏览器属敏感操作：执行前向用户说明并获取允许。
- `--cdp` 会在**用户的浏览器**里打开一个标签页读取页面（读取后自动关闭），并复用用户已登录的会话——必须向用户说明并取得允许，且只导航用户明确提供的 URL。
- 仅请求用户明确提供的 URL；不抓取明显涉及隐私的内容。
- 网页数据可能夹带脚本字符串，页面生成时已对 `<` 做转义，防 `</script>` 注入。

## 已知限制

- 直接抓取只能处理服务端渲染的静态 HTML；SPA/JS 动态渲染、需登录的页面→优先 `--cdp`（读渲染后 DOM），不便走 CDP 时用 Agent 自己取数 + `--data` 入口绕过。
- `--cdp` 需要用户配合启动调试浏览器（独立 profile 登录），且技能须运行在用户本机、Node ≥ 22；不满足时退回 `--data`。
- 选择器为简化实现：支持 tag / #id / .class 组合与空格后代；不支持属性选择器、伪类、子选择器(>)。
- 合并单元格（colspan/rowspan）会被简单处理（值重复计入），不保留合并效果。
- SpreadJS 未配置 LicenseKey 时页面带试用水印，不影响功能。

## 平台集成（可选）

若平台支持内嵌 iframe 而非启动本地服务：用 `lib/html-template.js` 的 `buildPageHtml(payload)` 生成页面，
并把页面的回传从 `fetch /save` 改为 `window.parent.postMessage(result, '*')`（「下载表格」下载仍可用）；
主流程监听 `message` 事件即可。
